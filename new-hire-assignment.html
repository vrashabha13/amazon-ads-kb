The Problem

Build a system that continuously acquires and maintains knowledge.

Not a static knowledge base — a dynamic knowledge acquisition system.

Imagine you run an Amazon Ads consulting company. Every week the landscape shifts: Amazon ships new docs, APIs change, blogs post guides, repos and MCP servers appear. You need one reliable source of truth that stays current and accurate.

1
Discover
Find new information from multiple sources
2
Extract
Pull out the key facts from each source
3
Validate
Check it against what you already have
4
Merge
Combine duplicates into one entry
5
Publish
Save it as OKF documents
It must be safe to re-run: run it twice and you get the same result, with only the real changes applied. So you'll need to think about what changed, what counts as the same topic, and where each fact came from.

Key Requirements

Four critical constraints shape the solution.

OKF Storage Format

Store everything as Google's Open Knowledge Format — plain markdown with a bit of metadata at the top. It pushes you to decide what belongs in one document and how concepts connect.

Standard, portable, readable by people and AI

Safe to Re-run

Running the pipeline twice must not duplicate anything. Spot what changed, update only the affected entries, leave the rest alone. So you'll think about what counts as the same item and how to detect updates.

No duplication on re-runs, sources kept track of

Know Where Facts Come From

Every fact should trace back to its source. Track how sure you are, how many sources confirm it, whether it's official, and when it was last checked. This keeps AI-made-up content from becoming "fact".

Sources always recorded, no unchecked AI output

Deduplicate & Merge

If 5 sources all describe "Sponsored Products," make ONE clear document that combines them — not 5 copies. When sources disagree, trust the official ones and note it.

One document per topic, clear sources

Tools & Approach

Build it as a Claude Code project — no SDK, no new framework.

Your deliverable is a repo we can git clone and run with claude. Claude Code is both the tool you build with and the platform you build on.

Compose, don't over-build. The native building blocks carry the whole pipeline:

  • Pipeline roles (Scout, Extractor, Validator…) become subagents
  • Formatting, dedup & citation rules become skills
  • "Validate before write" becomes a hook
  • Scope & behavior live in CLAUDE.md; output is the OKF bundle
One real choice: how much does code do vs. how much does Claude decide? Fetch / parse / hash / validate / write are deterministic — code does them well and they're testable. What's a concept, extracting facts, merging disagreements are fuzzy — Claude's job. Pick the line and explain it.
your-system/ 
your-system/
├── CLAUDE.md          ← behavior & scope
├── .claude/
│   ├── agents/        ← roles as subagents
│   ├── skills/        ← OKF, dedup, citations
│   └── settings.json  ← hooks: validate first
├── scripts/           ← helpers (optional)
└── knowledge/         ← the OKF bundle
run it 
$ claude -p "ingest <url>, update the bundle"

Tip: native web search may be off on your plan — add an MCP (e.g. Playwright + a search MCP) so the agent can fetch sources. The brief has a starter kit.

Getting Started

From zero to your first run.

Roughly 30 minutes to get you started. If a command differs on your machine, skim the official docs — don't get stuck here.

  1. Get a terminal & Node.js 18+. Windows: run wsl --install in PowerShell (reboot), then use Ubuntu. macOS/Linux: you're set. Make sure node --version is 18 or higher.
  2. Install Claude Code. npm i -g @anthropic-ai/claude-code, then run claude and sign in with the access we provide.
  3. Add MCPs for web access. claude mcp add playwright npx @playwright/mcp@latest (fetches JS pages), then add a search MCP — Tavily or Brave (grab a free key).
  4. (Optional) format normalizer. pip install markitdown — turns PDF / docx / HTML into markdown so you don't hand-parse each.
  5. Scaffold the project & git. Make a folder — e.g. amazon-ads-kb — git init it, then add CLAUDE.md and a .claude/ directory (e.g. agents/, skills/, settings.json).
  6. Smoke-test the loop. claude -p "fetch <an Amazon Ads URL> and summarize it" — prove fetch → read works end to end, then commit. Shaping that into proper OKF concepts is the assignment ahead.
